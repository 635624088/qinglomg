# 会话过期一次性重登录

## 范围

循环 worker 仅在协调令牌和 `desiredState=running` 仍有效、且健康窗口内尚未恢复过时，以既有 2 秒首档启动一个全新 worker。每次启动生成不可复用的 `runId`；只有同一 `runId` 写入的 `session-expired` 状态才可停止该实例，旧状态文件不得影响重登录后的新 worker。

`business-rejected` 保持受保护的业务语义；仅其附带的结构化响应对象含 `type:90000` 时，才归类为会话过期。文本中的 `unauthorized`、重新登录提示或 JSON 片段均不足以覆盖业务拒绝。

## 边界

新 worker 重新执行既有完整登录和权威状态拉取流程；不重放触发 90000 的业务请求。首次启动尚未 `automationReady` 即收到会话过期时，只有带有效协调令牌、`restartAttempt=0` 的意图会交给同一恢复协调入口；用户停止、令牌或设置代次变更不会启动恢复。十分钟健康进度后才重置恢复次数；第二次失效进入阻止状态，等待人工验证。
