# 花笺集芳最小官方流程

## 范围

账号级父开关 `autoHandleCyclicNote` 默认关闭。关闭时仅显示花笺集芳的活动和任务进度，不自动 `enter`、推进或领取。开启后才允许处理当前活动；运行时 `AUTO_HANDLE_CYCLIC_NOTE=0` 始终强制总停用。状态以一次 `gs.actCyclicNote.enter({ batchId })` 返回的官方快照为准，不从旧状态或本地推断进度。

`autoCompleteCyclicNoteHighestRewardTask` 是独立保留持久化值的子策略：开启时按集芳笺（item `1107`）奖励降序、槽位升序优先；关闭时按槽位顺序处理全部可支持的未完成任务。任一候选实际无法产生动作时，才尝试同一权威快照中的下一可支持候选，避免长期饿死其他任务；单次真实业务动作仍复用既有单动作 handler，并在动作后重新 `enter`。

## 权威状态

- 活动必须处于官方时间计算出的阶段 2。
- 任务槽位必须严格为 `taskList` 的三个槽位。
- 任务进度和领取状态只读 `actTot.taskRcdMap[`${batchId}|0`]` 的 `progress`、`recvMap`。
- `progress` 缺少某个任务键按 `0`；已有键必须是有限非负安全整数原始 `number`。
- 权威 map、当前记录、`progress` 或 `recvMap` 缺失时仅显示“等待官方数据”，不生成动作。

## 动作闭环

1. `enter` 后读取并总结三个槽位。
2. 先对全部权威 `canReceive` 槽位各调用一次 `gs.actCyclicNote.recvTaskRwd({ batchId, taskId })`。
3. 发送领取后再次 `enter`；只有 `recvMap` 明确显示已领取才算完成。
4. 没有可领取槽位时，按子策略排列安全、可支持的未完成槽位；候选无动作时再检查下一候选，成功动作后立即停止并再次 `enter` 刷新。
5. 不安全、未知或不支持的任务本轮无动作，且不阻断其他安全候选。

当前支持的任务类型映射：`1009` 居民订单、`1010` 珍珠雇佣、`3001` 种植、`3002` 收获、`3014` 浇水、`3015` 花架、`3016` 顾客订单。

## 明确禁止

不调用 `directRecvTaskRwd`、刷新/重随机、解锁、礼物、商店或其他花笺集芳捷径；不以请求返回成功推断进度。
